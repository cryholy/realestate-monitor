# /rem-trend — on-demand 트렌드 판독 커맨드 설계

2026-07-31. 브레인스토밍·backtest 2회(급매·상대강도)를 거쳐 확정된 매수 framework v1을
세션 커맨드로 고정한다. 주간 푸시가 아닌 **호출식(pull)** — 긴급 이벤트는 기존
monitor cron + alert_rules가 이미 푸시하므로 역할이 겹치지 않는다.

## 목적

`/rem-trend` 호출 한 번으로 서울 9개 구 + 관심단지의 시장 판독문을 생성한다.
정체성: **"잘 사기(안 비싸게·강한 걸로·칼 피해서) 도구"이지 사이클 타이밍 신탁이 아니다.**
중립 원칙 — 신호와 판정 규칙만 제시, 매수/관망 단정 없음. LLM 산문 없음.

## 형태

- 파일: `~/personal-labs/.claude/commands/rem-trend.md` (rem-run.md와 동일 패턴)
- frontmatter: `description`, `argument-hint: "[telegram]"`,
  `allowed-tools`: Supabase MCP execute_sql + Bash(curl:*) (텔레그램 발송용)
- 실행 주체: 커맨드 지시문을 따라 세션의 Claude가 ①~④ SQL을 MCP
  `execute_sql`(project_id `flsbxpjywjuhylfwnrby`)로 실행 → ⑤ 판정 규칙을 기계적으로
  적용 → 판독문 조립.
- 출력: 기본 터미널. `$ARGUMENTS`에 `telegram` 포함 시 scratchpad에 파일로 쓴 뒤
  시스템 curl로 발송 (`.env`를 `set -a; . ./.env`로 로드, 토큰 미출력, 4,096자 확인,
  응답 `ok:true` 검증). 로컬 Python은 TLS 프록시에 막히므로 curl 고정.

## 신호 정의 (v1-lean — 중립·신호만, **판정 없음**)

STAGE 1 수렴(myloop-converge, converged=false)에서 검토/대기 판정 기계가 **검증되지
않음**이 드러나 제거했다: A2는 2창 ①로 계산 불가(3창 재설계는 미backtest 발명),
B3 하드플로어 0.40은 강남3구 영구 veto(설계결함), (A1 or A2)→검토 진리표는 A1
재프레이밍과 내부모순. 게다가 이진 판정은 2코호트·14개월 backtest가 감당 못하는
확신을 함의한다. → ⑤는 판정을 내리지 않고 **후보별 신호를 한 줄에 병치**해 사람이
판단한다(회원님이 고른 "중립—신호만"과 일치). 전부 ①③④ frozen 결과에 산술만.

**후보별 신호 행** (①③④에서 산술, 추가 SQL 없음)
- **편차**: ④ 후보 최근 정상매물(3층↑·중개거래) vs 자기 180일 중위 편차%
- **급매(A1)**: 편차 ≤ **−8%** → `🔴급매` (backtest: 상승국면 회복 58% < base 91% →
  "왜 이 단지만 약한가" 조사 신호. **매수 신호 아님**)
- **고가**: 편차 ≥ **+3%** → `🔵고가`
- **칼(B1)**: 후보 구의 동일단지 모멘텀(①) ≤ **−3%** → `⚠칼(구 하락)`
- **쿠션(B3)**: 후보 구의 전세가율(③) 수준·방향 → `쿠션 얇음(<0.40)` 등 **표시용
  캐비엇**(게이트 아님 → 강남3구 영구 veto 소멸)
- **orphan**: sgg_cd 매핑 불가 시 구 기반 신호(칼·쿠션)는 `구 매핑 불가`로,
  '거래없음'과 구분

**상대강도**: ① 순위를 그대로 노출(참고용). backtest상 추세장 4/5 지속하나 크기
작고(~1–4pp) 전환점 역전 → "참고용" 명시. 거래량 국면은 ②에 표시하고, 최근 완결
2개월 < 직전 3개월 × **0.7**이면 "거래량 둔화 — 상대강도 참고 주의" 캐비엇 1줄만.

**제거**: A2 국면전환, 검토/대기 이진 판정, 전환스위치 하드 트립.

## 무조건 반영 (STAGE 1 패널의 정당한 교정 — 결정 무관)

- **SQL 필터 복제**: ②③④가 별도 SQL이면 `cancel_type IS DISTINCT FROM 'O'`(신고가후
  취소 오염), ③ 전세 median `monthly_rent_만원 = 0`(순수전세) 필수. ④ 저층(≤2)·직거래
  제외는 **분자·분모 대칭**.
- **데이터 신선도 1줄**: sale_records 최신 deal_date + 경과일. 수집 cron 실패 시 전
  후보 '거래없음→정상처럼 보임' silent misread 차단(trust-boundary 재무안전 가드).
- **golden 스냅샷**: 2026-07-29 ①~④ 숫자를 커밋 파일로 확보(첫 호출=골든 자기증명
  방지). 천장: 두 검증층 모두 ①~④ **수치 정확성(median/창경계 SQL 버그)은 못 잡음**
  — 스냅샷일 1회 수기 크로스체크로 대체, 명시.
- **확정 사실**(가정 아님, 실제 세션 SQL): ③ = ratio-of-medians(`j_median/s_median`,
  순수전세), ④ = 지배평형 1개·단일 최신거래·−45d 버퍼 미적용.

## 검증 (날짜 드리프트 명시 처리 — 2계층)

- **선행: golden 스냅샷 커밋** — 2026-07-29 ①~④ 숫자를 파일로 고정(없으면 첫 호출이
  골든이 되는 자기증명).
- **계층 1 (구조·날짜 무관)**: ①~④ 무에러 실행 + 기대 컬럼명 + 항상 출력분(9구 표
  9행, 후보 표 N행[N=0 규정], 신호 열, 고정 문구) 존재.
- **계층 2 (신호 산술 재현·날짜 무관)**: golden 스냅샷 숫자를 ⑤ 신호 정의에 대입 →
  기대 신호 라벨(급매/고가/칼/쿠션)과 대조. 위해 판독문 출력 템플릿(문구·소수 자릿수·
  컬럼 순서) 고정.
- **천장(ponytail)**: 두 계층 모두 SQL 수치 정확성은 못 잡음 → 스냅샷일 1회 수기
  크로스체크. 완전 수치 회귀는 범위 밖.
- **telegram**: 1회 실발송(ok:true, 4096자 이내, 초과 시 요약본 상한).
